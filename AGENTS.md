# skills agent guide

Portable agent skill catalog: self-contained skills for ChatGPT and Codex
agents, published as the `ega-skills` plugin (`plugin.json`, manifest schema
1.0.0). Skills use progressive disclosure: SKILL.md routes, `references/`
deepens, `scripts/` decide deterministically.

## Skill anatomy

Every skill is a folder under `skills/<skill-name>/`:

- `SKILL.md` — YAML frontmatter (`name`, `description`) plus the workflow.
  The description is the routing surface: include the trigger phrases an agent
  or user would actually say (see `adversarial-review` for the pattern).
- `ega.yaml` — EGA agent metadata.
- `agents/openai.yaml` — OpenAI agent metadata. Owned by
  `scripts/sync_openai_yaml.py`; do not hand-edit what the sync owns.
- `references/` — deep material (rubrics, schemas, contracts). Copy
  `references/operating-contract.md` into a skill's `references/` when the
  skill relies on those terms; never redefine shared vocabulary locally.
- `scripts/` — deterministic validators bundled with the skill.

`plugin.json` owns the catalog manifest (name, version, keywords, OpenAI
interface block). `references/agent-plugin-schema-1.0.0.json` (+ `.sha256`)
pins the manifest schema.

## Validation

Python 3.12. Install pinned deps first; pins are exact (`==`) — never float them:

- `python3 -m pip install --disable-pip-version-check -r requirements-ci.txt`

Run the same gates CI runs (`.github/workflows/catalog-validation.yml`), in order:

- `python3 scripts/validate_plugin_manifest.py`
- `python3 scripts/validate_catalog.py`
- `python3 scripts/sync_openai_yaml.py --check`
- `python3 scripts/sync_operating_contract.py --check`
- `python3 scripts/routing_audit.py`
- `python3 scripts/trigger_audit.py`
- `python3 scripts/validate_ega_metadata.py`
- `python3 -m unittest discover -s tests -p 'test_*.py' -v`
- `git diff --check`

All gates must pass on the change. A new skill needs its SKILL.md, ega.yaml,
and agents/openai.yaml plus a passing catalog validation before review.

## Conventions

These are enforced by `scripts/validate_catalog.py` — run it instead of
memorizing them:

- Skill names match their directory and follow `^[a-z0-9]+(-[a-z0-9]+)*$`:
  kebab-case verbs of the job, e.g. `certify-release`, `blast-radius`.
- SKILL.md frontmatter allows ONLY `name` and `description` — nothing else.
- Every skill has `agents/openai.yaml` with valid interface metadata.
- Every relative reference inside a skill must resolve; no empty
  `references/`, `scripts/`, or `assets/` directories.
- No placeholders, TODOs, or Cursor-specific coupling anywhere.
- `upstream-sources.json` records provenance; it is generated by
  `scripts/build_upstream_sources.py`, never hand-edited.
- SKILL.md states when to use AND when not to use the skill; name the
  neighboring skill that owns the adjacent job.
- Keep generated files generated: if a sync script owns it, fix the source and
  re-run the sync; do not patch the output.
- Keep `plugin.json` version in agreement with every manifest that carries it.

## Boundaries

- ✅ Always: run the full gate sequence before claiming a change is done; keep
  the operating contract the single source of shared vocabulary.
- ⚠️ Ask first: changing the manifest schema version, adding a new top-level
  directory, changing CI permissions.
- 🚫 Never: commit secrets or credentials; hand-edit sync-owned files; weaken
  a validator to make a failing skill pass; float a pinned dependency.

## Pull requests

Target `main`. One skill (or one coherent catalog change) per PR. The PR body
states what changed, which gates ran, and their results. Leave PRs open for
owner review; do not merge without owner authorization.
